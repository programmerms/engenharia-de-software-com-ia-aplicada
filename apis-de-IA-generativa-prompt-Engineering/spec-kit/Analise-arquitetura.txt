INTENÇÃO DO FLUXO:

A mensagem do usuário deve ser enviada para um nó de identificação de
intenção.

Esse nó deve utilizar LangChain + LLM + Structured Output.

O resultado deve utilizar um conjunto controlado de intenções:

- schedule
- cancel
- unknown

A IA pode interpretar diferentes formas de linguagem natural, mas o
resultado consumido pela aplicação deve respeitar esse contrato.

Exemplos:

"Quero marcar uma consulta"
"Gostaria de agendar uma consulta"
"Preciso consultar um médico"

devem poder ser interpretados como:

schedule

Da mesma forma, diferentes formas de solicitar cancelamento devem resultar
em:

cancel

O resultado da IA não deve ser utilizado para executar diretamente regras
de negócio.

O resultado estruturado deve ser colocado no estado do LangGraph.

O LangGraph deve utilizar esse estado para decidir o próximo nó.

FLUXO ESPERADO:

START
  ↓
identify_intent
  ↓
conditional routing
  ├── schedule → scheduler
  ├── cancel   → canceller
  └── unknown/error → message
                         ↑
scheduler ───────────────┤
canceller ───────────────┘
                         ↓
                      END

O nó scheduler deve utilizar um serviço de domínio para realizar o
agendamento.

O nó canceller deve utilizar o mesmo serviço de domínio para realizar o
cancelamento.

O nó message deve utilizar o LLM para gerar uma resposta natural ao
usuário baseada no resultado da operação.
